# A股每日市场数据采集 (daily-market) — 设计方案

> 状态：**方案待门1 review**。本文为设计 SSOT。操作 runbook 见 `skills/scheduled-ingest/jobs/daily-market.md`（实现阶段产出），取数脚本 `skills/scheduled-ingest/scripts/fetch_daily_market.py`。
>
> 来源：两轮 grilling 收敛（2026-06-29）+ 内容迭代（2026-07-01）。

## 1. 背景与定位

每交易日盘前自动采集**真·日变的原始市场信号**，落月度滚动日志，作为 periodic-review 的**高频市场底座输入**。

- **不做分析/判断** —— regime 合成、估值区间判定、叙事均留 periodic-review 手动层。
- **不替代 periodic-review 的采集** —— 个股 / 汇率 / 宏观数字 / 政策 / 资讯 / regime 仍归 periodic-review。daily 只接管**高频原始市场信号 + 两融**。
- 用途：A股/中概**高频市场信号**的择时背景层；periodic-review 复用其时间序列丰富"最近市场状态"。

### 设计演进留痕（grilling + 迭代反转记录）

| 决策 | 初稿 | 终稿 | 原因 |
|---|---|---|---|
| 个股盯盘 | 全 16 focus 现价+距锚+区间档 | **删** | 区间判定=判断，归 periodic-review 手动 |
| 慢变量 | PE 分位 / 指数波动 regime / 汇率 入日采 | **删**（回 periodic-review 按需） | 分位/滚动波动/管制汇率日变≈0，空转 |
| 宏观+资讯 | daily Tier2 预采+校验 | **删**（走 periodic-review） | 偶发事件，判断密集，不该塞日采 |
| 数据纪律 | 机械豁免（L1 only） | **不豁免 → 轻校验层** | 防单源陈旧/错值静默入库 |
| 与 periodic-review 关系 | "代替" | **底座输入 + periodic-review 调整复用** | 砍到最后，daily 是新增高频底座非替代 |
| 板块 | 概念板块（题材热点） | **改一级行业全表** | 用户要行业口径，非概念题材 |
| 行业指标 | 净额 + 成交额(流入+流出 proxy) | **涨跌% + 真实成交额，删净额** | 用户：净额没用；成交额要真实口径(指数历史)，可回填 |
| 市场级资金 | 主力净流入 + 南向净流入 | **删** | 用户：行业级资金更有用，市场级冗余 |
| 数据源 | 多处东财 push2 | **全改非-eastmoney** | push2 间歇/阻塞（见 §3.2 踩坑）→ 正常沙箱即可跑，无单点 |

## 2. 架构

```
daily job (每交易日 08:00 auto, 正常沙箱, 无 eastmoney/push2 依赖)
  └─ 采信号 ─→ 轻校验(交叉源/新鲜度/sanity) ─→ wiki/journal/daily/YYYY-MM.md + raw/JSON
        大盘指数 · 成交额 · 涨跌停 · 两融 ｜ 一级行业全表 ｜ 恒科·恒指 ｜ 金龙·纳指·标普
                              │
            periodic-review (手动) ◀── 读复盘窗口内全部 daily 节的时间序列 → 丰富"最近市场状态"+市场分析
                              └─ 自采:个股/汇率/宏观/政策/资讯/PE分位/指数波动 (照旧)
```

## 3. daily job 规格

### 3.1 触发与时点
- Claude app 定时任务，每工作日 ~08:00 CST。**正常沙箱即可**（无 eastmoney 依赖，无需 `dangerouslyDisableSandbox`）。
- **交易日 guard**（待建）：昨日非 A 股交易日（周末/节假日）→ 静默跳过，不写空节。
- 时点语义：覆盖 **T-1 A股/港股收盘 + 隔夜美股（最新）**，为 T 日盘前底座。

### 3.2 采集信号与数据源（2026-07-01 实测✓，正常沙箱全绿）

| 组 | 信号 | 主源 | 校验/交叉 | 口径 |
|---|---|---|---|---|
| **大盘指数** | 上证 / 深成指 / 创业板 / 沪深300 | 腾讯 `sh000001,sz399001,sz399006,sh000300` (`f[32]`) | 单源 | 点 + 涨跌% |
| **A股** | 成交额(两市) | 腾讯 `f[37]`(万元) | **双源**↔新浪 `stock_zh_a_spot` `成交额`求和 | 万亿元 |
| **A股** | 涨跌停情绪 | 新浪 `stock_zh_a_spot` 派生 | sanity 涨停≤上涨 | 涨/跌/涨停/跌停家数 + 赚钱效应 |
| **A股** | 两融余额 | akshare `margin_sh`+`margin_sz`(交易所) | 单源 + Δ 自序列 | 亿元（T+1 滞后一日正常） |
| **一级行业** | **申万一级 31 行业 涨跌% + 成交额 + 估值** | **`index_hist_sw`**（逐行业指数日 K：日度取最近收盘、回填取截至目标日）+ **`sw_index_first_info`**（估值 1 call）| 单源 | 涨跌% + 成交额(亿, Σ31≈市场100%) + PE_TTM/PB/股息率，**统一日 K 路径** |
| **港股** | 恒生科技 / 恒生指数 | 腾讯港股 `hkHSTECH` / `hkHSI` | 单源 | 点 + 涨跌% |
| **隔夜美股** | 中概金龙 KWEB / 纳指100 `^NDX` / 标普500 `^GSPC` | yahoo | 单源 | 涨跌%（最近美股收盘） |

> **趋势 Δ**：两融用交易所序列（实时）；成交额用自身 raw 归档（逐日累积，首日 —）。指数/行业/港股/隔夜的日变已含在"涨跌%"里，不另算 Δ。

> **实测踩坑（据此定源，全部非 eastmoney）**：
> - `activity_legu`（乐咕，原涨跌停源）**已死**；东财 `spot_em` 间歇+慢 → 涨跌停 + 成交额交叉源**统一新浪 `stock_zh_a_spot`**。
> - 恒科 yahoo `^HSTECH` 无数据 → **腾讯港股 `hkHSTECH`**；金龙交叉源 `^HXC` 无数据 → KWEB 单源。
> - **东财 push2 系全线不稳**：主力 `stock_market_fund_flow` / 南向 `hsgt_summary_em`（间歇）、东财行业 `board_industry_name_em`（`17.push2` 硬阻塞）、`stock_sector_fund_flow_rank`（`push2` 分钟级间歇）。→ 主力/南向按用户要求**删**；行业最初改**同花顺** summary（非 eastmoney），后于 2026-07-04 改用**申万一级 31**（见下条）；净额已删。
> - **一级行业口径（2026-07-04 定案：申万一级 31）**：初期误判"真·申万一级 31 无日频资金"而采同花顺 ~90；复测发现 `index_hist_sw`（申万宏源指数日 K）正好给 31 行业日频**涨跌%+成交额**（单位亿元，Σ31≈全市场、已对齐腾讯总额），`sw_index_first_info` 补 **PE_TTM/PB/股息率**。故改用申万一级 31（研究标准口径、31 行可扫视、附带估值），弃用同花顺 ~90（summary 接口时坏时好、无估值）。日度与回填统一走 `index_hist_sw`，无 realtime 盘前语义风险。
> - **结论：全信号非 eastmoney → 正常沙箱即可跑，push2 单点问题消除。**

### 3.3 信号灯档（静态阈值，机械套档）

> **提案默认，首跑后 ~20 交易日按实际分布校准。本表不构成对当前市场水平的断言。** 一级行业为**全表数值**（涨跌%+成交额+PE_TTM/PB/股息），不套档。

| 信号 | 档（待校准） |
|---|---|
| 成交额 | <0.8 萎靡 / 0.8–1.2 正常 / 1.2–1.6 活跃 / >1.6 过热（万亿，placeholder） |
| 涨跌停情绪 | 跌停多=冰点 / 均衡=中性 / 涨停多+赚钱效应高=过热（archetype） |
| 两融余额 | **复用现成四档**（🟢<25000 / 🟡25000–30000 / 🟠>30000 / 🔴>35000，见 `wiki/macro/A股两融余额追踪.md`；占比由 periodic-review 算） |
| 指数/恒科/恒指/金龙/纳指/标普 | 日变 <−2% 弱 / ±2% 平 / >+2% 强 |

### 3.4 校验（**不豁免**；机械可定义，仍 auto）

| 校验 | 做法 | 失败动作 |
|---|---|---|
| 交叉源 | 成交额 腾讯↔新浪，容差 ≤5% | 超差→标 [待核实] |
| 新鲜度 | 数据日期 = 预期交易日（防陈旧/周末日） | 陈旧→降级+标记 |
| sanity | 量级 + 内部一致（涨停≤上涨、成交额∈0.1–6 万亿等） | 越界→标记 |
| 单源项 | 指数/两融/行业/港股/隔夜（无双源）→ 仅新鲜度+sanity | — |

- 失败 → **降级 [待核实] + 节顶部列「⚠️ N 项未过校验」，不阻塞其余**。
- raw JSON 落 `raw/articles/market/YYYY-MM/YYYY-MM-DD.json` 作审计链（含 extra.indices / extra.industry 全量）。

### 3.5 输出
- 写入 `wiki/journal/daily/YYYY-MM.md`，当日节 `## YYYY-MM-DD (盘前)` **置顶（时间倒序，最新在最上）**，幂等（重跑替换）。
- 节内顺序：校验行 → **大盘指数行** → **A股层表**(信号/读数/Δ/灯/校验) → **一级行业全表**(申万一级 31 行，行业/涨跌%/成交额/PE_TTM/PB/股息，**截至最近完整交易日**，按涨跌降序) → **港股表** → **隔夜表**。行业块头部标注数据日期；历史日可用 `--backfill-industry YYYY-MM-DD` 回填（就地替换行业块，不动其它信号）。**无叙事/判断**。
- frontmatter：`tags: [每日市场, 数据]` / `updated: <最近写入日>`。

### 3.6 纪律
- **轻校验层**：强于 L1（交叉源+新鲜度），无需 L2 原文核对（聚合数无 canonical URL）/ L3 subagent。
- 破极值/历史首次：daily **只记数，不下断言**（断言=分析=periodic-review）。
- 只写自己的月度日志，**不碰 wiki 其它页**（两融追踪 / 宏观边际变量等更新仍归 periodic-review）。
- pre-commit hook 机械守隐私/frontmatter/术语；**auto-commit；push 手动**。

## 4. periodic-review 调整
- **读 daily 月度日志**：复盘窗口内（上次复盘 → 今）全部 daily 节的时间序列（成交额/涨跌停/两融 + 一级行业轮动 + 恒科/恒指 + 隔夜），丰富"最近市场状态" + 市场分析（喂 Step 2.5 / 报告）。
- **两融改读 daily**（删自采 1G）。
- 其余采集（个股 1A / 汇率 1B / 宏观 1C / 政策 / 资讯 1D–1F / 1H / 指数 1I / PE 分位）+ 分析层（Step 2.5/3/4）**不动**。
- 触发：手动。
- 接口契约：daily 日志节须**机器可解析**（固定表头 / 行业表固定 3 列），供 periodic-review 提取时间序列。
