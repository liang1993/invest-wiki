## 数字 Sanity Check 详解

写入具体数字前必须完成六项自检。

### 1. 口径双列强制

凡涉及"份额/持仓/市值"等易混淆指标，表格必须**分列两个口径**：
- ETF：分"基金总份额 / 机构持仓份额"
- 公司：分"营收 / 扣非归母 / 经营性现金流"

禁止单列笼统写"份额 XX 亿"。

### 2. 反推校验

写入派生数字（机构持仓占比、同比/环比变化率等）前，手动用"分子/分母"反推一次。
若结果 > 100% 或与基数明显不一致 → 口径错。
示例：写"机构持仓 735 亿 / 总份额 735 亿"→ 占比 100% → 立即报警。

### 3. 叙事去强化

见"精准/最激进/清仓/腰斩/80%"等强叙事词时，**默认标记为"待核实"**，直到能给出单一权威出处（基金季报 PDF / 官媒原文 / 公司公告）。

多篇二手媒体相互引用不构成可信来源。

### 4. 极端数字溯源

单项变动 ≥ 50%、或打破历史极值的断言，必须在同一次搜索里**贴出原始数据源的直接链接**（不是汇总文章）。
写不出来就不写，或标"估算（来源：XX 外推）"。

### 5. 估值假设三档溯源

估值锚点推导链上每个核心输入（合理 PE/PB/PS/PEG、历史中位/分位、同业对标、假设的 ROE/g/r/分红率）必须能回答"这个数字哪来的"。三档标注：

- **[观测]** — 数据源直接获取（标 URL：gurufocus / 巨潮 / 同花顺 / baidu / eniu 等）
- **[推算]** — 基于观测的运算（标公式，如 `BPS 内生增速 = ROE × (1-分红率)`）
- **[估计]** — 主观判断或外推（标 confidence 区间，如"假设合理 PE 6-8x，取中位 7x"）

**禁止**：
- 写"近 X 年中位 N"或"历史平均 PE M"而不附数据源
- **用分位数反推中位**（左偏分布系统性偏差，应直查中位）
- 把 [估计] 当 [观测] 写

能查就先查（30 秒成本），不能查就标 [估计] 并给区间。

### 6. 横向对标必查 + 比例反向校验

#### (a) 必查规则

无论觉得多"显而易见"，**强制 WebSearch 一次**。
原因：训练数据有时效断层（mid-2024 vs 当前），AI 对"常识性事实"的置信度系统性偏高。
横向对标数据是**估值锚点的载力输入**而非"背景常识"——所有用于推导估值的数字都是核心数据。

#### (b) 比例反向校验

写完一组横向对标后，手动算两两比例：

- **市值大小**应与公司业务范围一致：综合体（如 Samsung 手机+芯片+面板）> 纯主业龙头（如 SK Hynix 存储）≥ 同主业二三梯队（如 Micron 存储）
- **业务弹性 ≠ 市值绝对值**：HBM 周期下 SK Hynix 弹性 > Micron 弹性 > Samsung 存储板块弹性。弹性大 ≠ 市值大，别混用
- **PE/PS 倍数**应符合周期阶段：周期顶部 PE 偏低（8-15x，盈利高分母大）/ 底部 PE 偏高（25-40x）
- **中美/中港同业市值比**应符合 GDP × 行业渗透率量级：A 股纯主业龙头通常是美股对标的 30-60%（除非科创板独苗溢价）

不一致就回查。**内部一致的错误数据集是最难发现的失败模式**（如长鑫案例：Samsung 3.2 万亿 / SK 1.08 万亿 / Micron 8650 亿 三者比例自洽但绝对值全错）。

#### (c) 高时效衰减领域（每季度复审，下次：2026-08-20）

以下领域**任何超过 6 个月的记忆数据默认 [估计]**，必须 WebSearch 升级到 [观测]：

- HBM / AI 算力 / GPU / 存储芯片相关市值与财务
- 美联储利率 / 美债收益率 / 美元指数 / 主要汇率
- 中国房地产价格 / 销售 / 房企财务
- 中美关税 / 贸易摩擦相关数据
- 国家队 ETF 持仓 / 大基金动向
- **金价 / 油价**（2026-05-20 新增，金价 4 月仍 $4,700+ vs 训练记忆 $3,500 偏差 34%）

## 写入格式纪律

- 数字后括注口径与报告期，如 `735.13 亿份（汇金持仓口径，2025 年报）`
- "单周/单日/累计/YTD"等时间限定词与数字一一对应，不得混用
- 区间估算必须标"估"并给外推方法，如 `7,000-9,000 亿（估；按单只 ETF 减持线性外推）`
- 估值假设标来源档位，如 `合理 PE 6x [观测+政策溢价]：历史中位 5.07x（gurufocus）+ 央企市值管理 0.93x [估计]`

违反此规则导致错误的数据，应在 `log.md` 中以 `LINT` 条目公开记录根因。

## 数据校验 Agent prompt 模板

主 agent 完成 wiki 写入后，spawn `general-purpose` Agent。Prompt：

```
你是数据校验员，零主对话上下文。本次 ingest 涉及的原始材料：
- [列出 raw/articles/、raw/reports/ 路径 + 主要 PDF/URL，若无则写"无"]
- 本次新写入/修改的 wiki 页面：[文件路径 + 关键章节定位]

任务：从修改后的 wiki 内容里提取**所有具体数字**（市值、营收、利润、PE、份额、利率、汇率、宏观指标、增速、占比等），逐项判定来源类型并校验：

1. **可溯源** — 在原始材料里找到（贴页码或原文摘录）→ ✓
2. **派生计算** — 由原始材料 + 公式推出（如 PB = 价格/BV）→ 验算一次，一致标 ✓
3. **横向对标 / 时效数据** — 不在原始材料中（对其他公司的市值/PE/份额、当前汇率/利率、行业均值、同业对标），**禁止凭训练数据记忆判断**，必须 WebSearch 核对 → "一致 / 偏差 ±X% / 无法核对" 三档
4. **无法核对** — 无原始材料、search 也查不到 → ⚠️

特别注意 docs/data-discipline.md §6(c) 高时效衰减领域，>6 个月记忆数据必须 WebSearch 升级到 [观测]。

返回报告格式：
- **若全部 ✓ → 只回一行：`通过 (扫描 N 项)`**，不写其他
- 否则只列 ✗ / 偏差 > 10% / ⚠️ 项
- 每项注明：数字 / wiki 位置 / 偏差幅度或问题 / search URL / 建议修正
- 不要罗列全部 ✓ 项
- 末尾汇总：总扫描 N / ✓ M / 异常 K

预算：上限 10 次 WebSearch，超过后总结剩余可疑项让主 agent 自查。
强制：每个偏差或 ⚠️ 判断**必须附 search URL 或原始材料引用**——无来源的判断本身不可信。
```

## 两阶段分离工作流详解

> 2026-05-20 引入。CLAUDE.md「Wiki 数据写入工作流」章节的展开版。

### 设计动机

同型错误连续 3 次（详见 [历史教训索引](#历史教训索引)）：
- 2026-05-19 长鑫科技 v0 横向对标——Samsung/SK/Micron 市值凭 mid-2024 记忆全错
- 2026-05-20 早 消费趋势 4 月金价 $3,500（实际 $4,720）
- 2026-05-20 晚 4 月信贷深度注解——中国房贷/GDP "17%" 实际 26% + 虚构"2024-07 -767 亿"

共同根因：**主 agent 在"洞察叙事"流中跳过了 §6 横向对标必查 + §6(c) 时效自警等已有规则的执行**。

### 阶段 A：数据声明清单

写入 wiki 前必须输出，格式示例：

```markdown
## 本次数据声明清单（2026-05-20 4 月信贷注解）

| # | 数字 | 类型 | URL / 公式 / confidence |
|---|---|---|---|
| 1 | 2025-07 新增贷款 -500 亿 | [观测] | https://wallstreetcn.com/articles/3753238 |
| 2 | 2026 Q1 化债置换 9,604 亿 | [观测] | https://www.stcn.com/article/detail/3582131.html |
| 3 | 4 月单月化债扣减 3,000-4,000 亿 | [估计] | confidence 中等，按 Q1 月均 3,200 亿外推 |
| 4 | 还原后 4 月内生增速 7-8% | [推算] | (3-4 千亿) / (260 万亿 × 1/12) × 12 ≈ 1.4-1.8% 月增速 → 年化 5.6% 名义 + 化债扣减还原 |
| 5 | 中国房贷/GDP 26% | [观测] | 37.01 万亿 / 140.19 万亿 = 26.4%（新华网 + 新浪财经） |
| 6 | 日本 1990 房地产部门贷款/GDP ~100%+ | [观测] | ADBI WP558 |
```

清单未输出 → 不能进入阶段 B/C。

### 阶段 B：校验执行

**逐项执行**：

- **[观测]** 每项 `WebFetch` 原 URL（不接受 WebSearch 摘要），验证：
  - (i) URL 实际可访问（非 302 重定向到无关页）
  - (ii) 数字在原文完整句子中（不是 AI 摘要"估算"出来的）
- **[推算]** 每项列出公式 + 反推验算
- **[估计]** 每项标 confidence + 外推方法

**触发词扫描**（机械触发，不依赖判断）：

| 触发模式 | 必触发动作 | 历史教训案例 |
|---|---|---|
| 写"X 国 Y 指标 N%"（跨国/跨市场对照） | WebSearch + WebFetch | 中国房贷/GDP 17%（实 26%） |
| 写其他公司市值 / PE / 份额（同业对标） | WebSearch + WebFetch | 长鑫 Samsung/SK/Micron 偏差 2.6-6.7x |
| 写"YYYY-MM 单月数据 N 亿" | WebFetch 该月权威发布稿 | 2024-07 -767 亿（实 +2,600） |
| 写"同比/环比 ±N%"等变化率 | WebFetch 分子分母原始数据反推 | — |
| 写"近 X 年中位 / 平均 / 历史 PE N"（行业均值） | WebFetch 数据源直查（禁止分位反推中位） | 中国建筑 v1 PE 中位用分位反推 |
| 写"历史首次 / 创口径新高 / N 年以来" | WebSearch 历史对照 | — |
| 引用任何 URL 作为 [观测] 来源 | WebFetch 验证 URL 可访问 + 数字在原文中 | 腾讯新闻 URL 302 重定向 |
| 复用 WebSearch 摘要里的具体数字 | WebFetch 原 URL 核对 | 2024-07 AI 摘要错配 |

> **同源 URL 优化**：同一份 PDF / 网页内的多个数字只需 `WebFetch` 一次，在数据清单里按来源分组（标 `source: A` / `B` / `C`）。

### 阶段 C：写入 wiki

基于阶段 B **已校验数字**撰写。

**失败处理**：
- WebFetch 显示偏差 → 修正声明清单 → 重跑阶段 B
- URL 不可访问或数字不在原文 → 该数字降档 [估计] 或删除断言
- 不允许"凭印象保留数字"

### 阶段 D：subagent 数据校验

事后 spawn `general-purpose` Agent 兜底——详见上文"数据校验 Agent prompt 模板"章节。

### 成本与权衡

- **token 增量约 +15-20%**（多 5-7 次 WebFetch + 数据清单输出）
- **对话节奏变慢**
- **用户已明确接受**：数据正确性优先级 > token 节省 + 对话节奏（详见 memory `feedback_wiki_data_must_be_verified`）

### 与机械豁免的关系

豁免条件与"数据校验 Agent"章节一致：
- 纯文字修订（typo / 排版 / 链接维护）
- 撤销操作
- 0 新增数字断言且 0 改动已有数字

豁免不适用于**高时效衰减领域**（HBM/AI 算力、美联储利率、中国房地产、中美关税、国家队 ETF、金价/油价）——这类数字哪怕 1 处也强制走两阶段。

## WebSearch 归档（raw/articles/）

搜到的关键资料不再用完即抛，存到 `raw/articles/` 便于后续复用、二次核对、形成时间线。

### 目录结构

```
raw/articles/
├── stocks/<股票名>/<YYYY-MM-DD>_<主题>_<来源简称>.md
├── macro/<主题>/<YYYY-MM-DD>_<摘要>_<来源简称>.md
└── sectors/<行业>/<YYYY-MM-DD>_<主题>_<来源简称>.md
```

用 `find` 或 `grep` 检索，不做中央 index。

### 数据准确性硬要求

落库每条数据必须满足：

1. **原文摘录可核对** — 关键数字以**原文完整句子**形式引用加引号。AI 总结可能失真，必须 WebFetch 原 URL 回访核对
2. **原始 URL 完整** — `source` 字段必须是具体文章 URL，不得只写域名或搜索入口
3. **只归档原文披露的数字** — 别篇的数据另立归档文件，禁止在一篇归档里塞别篇数据
4. **抓取日期 ISO** — `fetched: YYYY-MM-DD`，不得用相对日期
5. **状态字段** — `verified: true / partial / unverified`：
   - `true` — 已 WebFetch 原 URL 核对，所有数字一字一致
   - `partial` — 部分数字核对过，其余来自 WebSearch 摘要
   - `unverified` — 未做回访核对（临时落库，应尽快转 true）
6. **矛盾保留两说** — 同一数据点不同来源不一致时**两个版本都归档**，frontmatter `conflicts` 字段互指

### 文件格式

```markdown
---
source: https://domain.com/path/to/article
fetched: 2026-04-24
title: 原文标题（一字不改）
publisher: 来源（新浪财经 / 上海证券报 / 公司公告等）
published: 2026-04-01
stocks: [中信证券]
topics: [Q1财报, 2026Q1]
verified: true
conflicts: []
---

# 原文标题

## 关键数据（原文已验证）
- {数据点}：{数字}（来自原文 "{完整句子引用}"）

## 原文摘录
> {关键段落引号引用}

## 被引用于
- wiki/path/to/page.md#章节锚点
```

### 反向引用

wiki "信息来源"或"数据来源"章节引用时同时写 `raw/articles/` 路径：

```
- [原文标题](URL) — 已归档 `raw/articles/stocks/中信证券/2026-04-09_Q1业绩快报_证券时报.md`
```

### 不归档清单（避免垃圾场）

- 一次性股价波动、单日新闻
- 纯观点性营销文（"机构看好"）
- 仅搜索结果页入口链接（无内容实质）
- 被 wiki 消化且不会再回看的老数据（>3 年且已被新数据替代）
- 低信号的重复报道（同一事实的多篇媒体，留信号最强的 1-2 篇）
