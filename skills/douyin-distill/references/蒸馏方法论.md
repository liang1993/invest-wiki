# 蒸馏方法论 — 把逐字稿提炼成"像他"的人设 skill

第 6 步的核心。读完逐字稿后照此产出 + 自检。三个已有样板：`macro-ellie` / `stock-kuaidao` / `invest-tusi`，**写之前先打开对照**。

---

## 一、人设 skill 产出结构（固定三件套）

```
skills/<persona>/
  SKILL.md
  references/
    <招牌方法>.md      # 他的方法论/框架库（斩股十刀 / 金融股=买资产 / 三周期…）
    <投资观/数据>.md    # 核心信条深版 + 估值观 / 或常用数据口径
    声纹与示例.md       # grep 频次 + 签名句式 + 范式 + 标注示例 + ASR 备忘
```

### SKILL.md 章节骨架（照搬顺序）
1. **frontmatter**：`name` + `description`——description 要写足**触发场景**（用户会怎么唤起）+ 一句"这是解读/风格层，取数/估值/业务走 XX skill"的分工。触发器写细，命中率才高。
2. **定位：是什么 / 不是什么**——尤其**和已有人设的分工**（别和 ellie/kuaidao/tusi 撞，写清差异点）。
3. **核心信条**（5–9 条）——他分析的"操作系统"，每条一句话 + 一句原话佐证。比模板更重要。
4. **方法论/招牌框架**（表格 + 指向 reference）——他的身份证（编号刀法 / 框架 / 周期模型）。
5. **输出结构与范式**（3–4 种范式，按输入选）。
6. **语气与遣词**（声纹摘要 + grep 频次，指向声纹 reference）。
7. **人设与价值观**——立场（散户代言/价投学者…）、**他卖什么**（不卖/卖书/卖会员，别照搬别人）。
8. **红线与边界**——不预测点位/不荐股/数字走取数 skill 核实/逐字稿例子非核实事实。
9. **references/ 索引**。

---

## 二、声纹 grep 蒸馏法（让"像他"可量化，别凭印象）

`声纹与示例.md` 必须包含：

1. **高频词表（grep 实测）**——别拍脑袋，真的数：
   ```bash
   cd $WD/transcripts
   for w in 牛逼 咱们 应该说 核心 框架 周期 资产 ...; do
     printf "%-8s %s\n" "$w" "$(cat *.md | grep -o "$w" | wc -l)"; done
   ```
   挑出显著高于日常的词（口头禅/转场词/评价词），标次数 + 用法。**也记"对比锚点"**：哪些词他几乎不用（如 tusi 段永平=0、无武侠词），用来和别的人设区分。
3. **签名句式**：开场公式、转场公式、过关/收尾公式、招牌反问——给真实例句。
4. **雷打不动的动作**（2–4 个）：如 kuaidao"现场手算 + 术语翻白话 + 戳假数字"；tusi"先抛框架 + 引经典 + 回到长期与估值波动"。
5. **生活化打比方 / 文学化**：他的辨识度细节。
6. **N 种范式**：把他的内容归成 3–4 类（深拆 / 短评避雷 / 科普 / 宏观…），各给骨架。
7. **标注示例**：取 1 条代表作，逐句标注"这是钩子 / 这是过关公式 / 这是免责三连"。
8. **ASR 错别字备忘**：人名/术语转写错的，列"正确=错写"，模仿时用正确写法。

> 频次数字写进 skill 后，**第 7 步校验会逐个复算**——偏差 >30% 或方向错会被揪。所以一次数准（在全部样本上数，不是子集）。

## 三、提炼信条与招牌方法（判断活，重点）

- **信条**：通读时记下他反复回到的"底层判断"（如 tusi"跟踪财报是为警惕长期变化不是预测季报""估值波动>>财务波动"）。每条要能在逐字稿里找到原话。
- **招牌方法**：找他的"身份证"——一套可复用的分析套路（kuaidao 斩股十刀、tusi 金融股=买资产/三周期）。把步骤、阈值、原话整理成 reference。
- **去污染 / 对人设**：
  - **别把别的博主的特征安上来**（武侠刀法是 kuaidao 的、无废话地缘是 ellie 的、学院派周期是 tusi 的）。
  - **如实写他卖什么**：ellie 不卖东西、kuaidao 卖书《快刀斩股》、tusi 卖会员/付费视频——直接影响"红线"怎么写。
  - 数字案例标清是 **ASR 转写、示范方法用、非核实事实**。

## 四、校验 subagent prompt 模板

第 7 步直接改用。spawn `general-purpose`，`model=sonnet`，`run_in_background=true`：

```
你是零上下文独立校验员。核对一个"抖音博主人设 skill"是否忠实于原始逐字稿，揪虚构/错配/夸大。不要客气。

待校验：skills/<persona>/SKILL.md + references/*.md（读全部）
事实源：<WD>/transcripts/*.md（N 份 ASR 逐字稿，唯一依据）

必须真的执行（grep/读文件逐条核对，别只看 skill 自洽）：
1. 声纹频次：声纹 ref 声称的每个 grep 数字，用 `cat transcripts/*.md|grep -o "词"|wc -l` 复算，偏差>30% 或方向错→标出。尤其确认"对比锚点"（声称=0 的词真的是 0）。
2. 招牌方法/框架：每套去逐字稿找原文支撑，找不到=虚构，标 ✗。
3. 关键数字/案例：逐条到 transcripts 验证，对不上标 ✗。
4. 核心信条：每条找原文句子支撑。
5. 抓虚构：skill 里任何口头禅/句式/信条/框架，逐字稿里找不到依据→✗。
6. 错配：有没有把别的博主特征安到他身上。

输出：先一行 `通过 0✗0⚠️` 或 `N✗ M⚠️`；再逐条列 ✗/⚠️（skill 原话 + transcripts 实际 + 文件:行）。预算 ~15 次 grep/read。只读不改。
```

收到报告后：✗ 必改，⚠️ 评估后改；改完用自己的 grep 复核关键项（频次自己也数一遍），不盲信 subagent。
