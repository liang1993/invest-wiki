# 车企月度销量 + 单车型 Top 变化

**Job ID**: `auto-monthly-sales`
**触发**: 每月 10-15 日（懂车帝次月 10 日左右发布）
**数据源**:
- **主源**：懂车帝 API — `https://www.dongchedi.com/motor/pc/car/rank_data`（详见 [`references/dongchedi-api.md`](../references/dongchedi-api.md)）
- 抓取脚本：[`scripts/fetch_auto_sales.py`](../scripts/fetch_auto_sales.py)

**目标**: 跟踪**车企月度销量变化 + 单车型 Top 变化**，支撑：
- 车企市占率走势
- 主力车型销量趋势
- → **前瞻分析车企经营状态**（销量是经营的滞后 1 个月指标，能比财报早 3 个月）

**输出三层结构**:
1. **车企集团合计**（市占率分析） — 比亚迪/吉利/长城/长安/奇瑞/鸿蒙智行/新势力 合计销量 + 同比 + 市占率 + 主力车型
2. **关注品牌矩阵**（主力车型变化） — 单品牌下所有 SKU 排序 + 同比
3. **全市场 Top 30**（趋势观察） — 含 last_rank 月环比信号

**写入目标**:
- `raw/articles/sectors/汽车/<YYYY-MM>_车企销量月度_懂车帝_yoy.md`（必写，含同比）
- `raw/articles/sectors/汽车/<YYYY-MM>_车企销量月度_懂车帝_wholesale.md`（按需，批发口径——做经销商库存对比时再跑）
- `wiki/sectors/汽车.md` 销量章节（**按需回写**，详见下文「回写条件」）

**校验级别**:
- **L1**：必跑——量级 + 同比异常值检查（见下文）
- **L2**：触发——同时改了 `wiki/stocks/auto/*` 销量假设才触发；仅 ingest 销量数据本身不触发
- **L3**：豁免——公开榜单 + 多源（API 数据稳定）+ 不动估值锚，可豁免

**失败处理**:
- 数据未发布（10 号前）→ 推迟到 12-15 号再跑
- API 超时 → 重试 1 次；持续失败用 `WebFetch` 兜底页面
- 关注车企掉出榜单 → 不太可能（API 给 638 款全榜）
- 数据 fallback 陷阱（传未来月不报错）→ L1 检查覆盖

## 步骤

### 1. 跑脚本

```bash
# 主跑：零售口径 + 同比 + Top 30 + 写 raw
python3 skills/scheduled-ingest/scripts/fetch_auto_sales.py \
    --month <YYYYMM> --yoy --top 30 \
    --raw raw/articles/sectors/汽车/
```

可选附加：

```bash
# 批发口径（与零售对比 → 渠道库存压力）
python3 skills/scheduled-ingest/scripts/fetch_auto_sales.py \
    --month <YYYYMM> --saletype wholesale --top 30 \
    --raw raw/articles/sectors/汽车/

# 能源类型筛选（关注新能源结构演变）
python3 skills/scheduled-ingest/scripts/fetch_auto_sales.py \
    --month <YYYYMM> --energy phev   # 仅插混
```

### 2. L1 自检（每月必做）—— **SSOT，cron prompt 引用本表**

| 检查 | 阈值 | 异常处理 |
|---|---|---|
| **API fallback 检测**（最关键）| **比亚迪集团当月合计销量** ≠ 上月该指标 | **完全相同** = API 返回 fallback 数据（数据未发布）→ 删除新 raw，等下次 cron 自然补抓 |
| 全市场总量量级 | **80-200 万辆**（含春节月可低至 100 万）| 偏离 > 50% → 数据异常，保留 raw 但标记需 review |
| 比亚迪集团合计 | 8-30 万辆/月 | 偏离 → 检查 brand_name 是否变化（OEM_PARENT_MAP 失配）|
| 关注品牌覆盖 | FOCUS_BRANDS 中 ≥ 80% 在榜 | 缺失 → 该品牌可能改名，更新 `OEM_PARENT_MAP` + 重跑 |
| 单车型同比绝对值 | 渲染时 > ±1000% 已自动 cap | 不阻断 ingest，但需注意基数过小车型 |

**为什么用「比亚迪集团合计」做 fallback 检测**：
- Top 1 车型（如星愿/Model Y）跨月可能换主角，导致误判
- OEM 集团级数据更稳定，比亚迪销量大、波动小、跨月变化 ≥ 5%
- 实测 2026-01 → 02 → 03 → 04 比亚迪集团合计：93,784 → 88,468 → 193,803 → 181,646（无两月相同）

**实施方式**：读刚写的 raw 文件，grep `^\| [0-9]+ \| 比亚迪集团 \|` 提取数字，与上月 raw 文件对比。

### 3. 分析维度（核心：经营状态前瞻）

读 raw md 后，按下列三个维度判断**车企经营状态**：

#### 维度 A：销量趋势（最直接，1 个月领先）

| 信号 | 判断 |
|---|---|
| 车企集团同比 < -20%，连续 3 个月 | 经营恶化，估值 P/S 应下调 |
| 车企集团同比 > +30%，连续 3 个月 | 高增长期，估值 P/S 可上调 |
| 车企集团同比 ≈ 0 但分车型差异极大 | **产品矩阵替换中**（如 2026-04 理想：i6 替代 L 系列），看不出长期方向，观察 1-2 月 |
| 全市场同比 > -10% 但车企同比 < -20% | 车企在丢份额（市占率下降）|

#### 维度 B：主力车型 Top 变化（更细，反映产品力）

| 信号 | 判断 |
|---|---|
| 主力车型（前 3 销量）排名 ↓ 10+ 名 | 产品力下降信号，需查竞品（同价位段） |
| 主力车型新上市（rank > last_rank + 50） | 爆款形成，验证产品定位 |
| 单车型同比 -50% 且无新车替代 | 产品生命周期末期，需新车导入 |
| 多车型同比 -30%+ 但 1 款车 +N00% | 单一爆款依赖，矩阵风险 |

#### 维度 C：批发-零售 gap（如跑了批发口径）

```
缺口 = (批发销量 - 零售销量) / 批发销量 × 100%
```

| 缺口 | 判断 |
|---|---|
| 缺口 < 20% | 渠道健康 |
| 缺口 20-40% | 正常库存 + 出口（如吉利/长城海外占比高的）|
| **缺口 > 50%** | **渠道库存压力大 + 出口未消化**，下月可能被动降价 → 毛利率下行警告 |

### 4. 回写 wiki 的条件（按需触发，不是每月都写）

**触发回写**（任一）：
- 车企集团**首次进入或跌出 Top 5**（如吉利首次超比亚迪）
- 关注新势力**月销首次破 X 万**（如蔚来集团月销首次 > 4 万）
- 季末（3/6/9/12 月）—— 同步刷新 wiki 季度销量数据
- 用户明确说「更新 wiki 销量榜」
- value-invest 触发个股估值修订时（需新销量数据支撑 P/S 锚）

**回写内容**：
- 替换 `wiki/sectors/汽车.md` 「核心格局」章节的销量表（用 OEM 视图）
- 在「信息来源」追加引用本月 raw 文件
- 不删除历史信号叙事（追加 2026-MM 行而非整段重写）

**禁止**：
- ❌ 每月强制回写 wiki（wiki 不是 dashboard）
- ❌ 直接改 `wiki/stocks/auto/*` 估值锚（那是 value-invest 的工作）
- ❌ 单月信号触发个股估值修订（需 2-3 月趋势确认）

### 5. 更新 log.md

```
INGEST auto-monthly-sales <YYYY-MM> 完成 (raw 已写, 关键信号: <简短描述>)
```

### 6. 与下游联动

如果月度数据显示某个 **focus 列表车企连续 2 月销量同比 -30%+** 或 **市占率连续 3 月下降**，主动提示：

> 「<车企> 已连续 X 月销量同比 -X%，建议用 value-invest 重新评估其 P/S 假设。」

但**本 job 不直接改 wiki/stocks/***——保持纪律：数据采集 vs 估值分析分层。
